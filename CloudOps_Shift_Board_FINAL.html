Setup — Power Automate connection
Connect to your SharePoint Excel using Power Automate — already included in your Microsoft 365. No extra accounts, no admin access needed. Takes about 10 minutes once.
This flow reads your Excel and sends all data to the dashboard. It runs under your Microsoft account using your existing SharePoint permissions — no Azure AD, no admin needed.
  • 1
    Go to make.powerautomate.com → sign in with your work Microsoft account → click + Create → Instant cloud flow.
  • 2
    Name it CloudOps READ. For trigger, search and select "When an HTTP request is received". Click Create.
  • 3
    On the trigger card, set Method = GET. Under "Who can trigger the flow?" select Anyone.
  • 4
    Click + New step → search Excel Online (Business) → select "List rows present in a table". Set Location = your SharePoint site, Document Library = the library, File = your Excel, Table = tbl_ZD. Rename this step Get_ZD.
  • 5
    Repeat step 4 seven more times for each table: tbl_Jira tbl_Limited tbl_Provisioning tbl_Information tbl_Project tbl_RemoteHands tbl_Handover. Name each step accordingly.
  • 6
    Add a final step: search Response → select the Request / Response action. Set Status Code = 200. Add header: Content-Type = application/json and Access-Control-Allow-Origin = *. In Body paste this expression (click the Expression tab in the value field):
    json(createObject('zd',body('Get_ZD')?['value'],'jira',body('Get_Jira')?['value'],'limited',body('Get_Limited')?['value'],'prov',body('Get_Prov')?['value'],'info',body('Get_Info')?['value'],'project',body('Get_Project')?['value'],'rh',body('Get_RH')?['value'],'handover',body('Get_Handover')?['value']))
  • 7
    Click Save. The trigger card now shows the HTTP POST URL — copy it and paste in the Enter URLs tab.
This flow receives updated data from the dashboard and writes it back to Excel. It clears and rewrites the relevant table on each save.
  • 1
    Create another new Instant cloud flow. Name it CloudOps WRITE. Trigger: "When an HTTP request is received", Method = POST, Who can trigger = Anyone.
  • 2
    In the trigger's Request Body JSON Schema box, click "Use sample payload" and paste: {"section":"zd","rows":[{"TicketID":"1","Organization":"Test","Subject":"Test","Status":"Done","Notes":""}]} then click Done.
  • 3
    Add step: Control → Switch. Switch on value: triggerBody()?['section'].
  • 4
    Add a case for each section name (zd, jira, limited, prov, info, project, rh, handover). Inside each case, add two actions:
    ① Excel → Delete a row — pick the matching table, Key Column = TicketID, Key Value = * (this clears all rows)
    ② Apply to each on triggerBody()?['rows'] → inside, add Excel → Add a row into a table and map each column to the matching field.
  • 5
    Add a final Response step: Status 200, Header Access-Control-Allow-Origin = *, Body = {"ok":true}. Save and copy the HTTP POST URL.
Tip: The WRITE flow is optional to start — you can use READ-only first (load data, view it, add rows manually in the dashboard, then export to Excel using the Save button). Add the WRITE flow when you're ready for full two-way sync.
From your CloudOps READ flow → trigger card → HTTP POST URL. Required for auto-loading data.
From your CloudOps WRITE flow. Leave blank to use manual export only.
These URLs are saved in your browser. Each team member enters them once. After that the dashboard auto-loads every time with no prompts.
